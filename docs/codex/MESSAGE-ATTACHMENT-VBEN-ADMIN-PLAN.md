# Vben 聊天附件管理实施方案

在 Vben 的「即时通讯管理 → 对象存储」现有页面增加聊天附件查询、引用诊断和受控运维。目标是让管理员能定位附件不可读、重复存储、清理失败、GIF 传播积压和兑换异常，同时保证私有附件继续按消息授权。实施范围为 IczpNet.Chat 管理 API 与 Vben `apps/web-antdv-next`。 [三端生产评估与修复顺序](MESSAGE-ATTACHMENT-PRODUCTION-READINESS.md)

## 现有入口与实施边界

- Vben 路由 `ChatBlob` 位于 `/chat/blob`，页面使用 `useVbenVxeGrid`、详情抽屉和编辑弹窗。沿用该路由，菜单名称调整为「附件与对象存储」。权限接入现有 `grantedPolicies`、路由 `meta.authority` 和按钮权限检查。 [Chat 路由](F:/Dev/abpvnext/abp-admin-vben/vue-vben-admin/apps/web-antdv-next/src/router/routes/modules/chat.ts:84) · [现有列表](F:/Dev/abpvnext/abp-admin-vben/vue-vben-admin/apps/web-antdv-next/src/views/chat/blob/index.vue) · [权限路由守卫](F:/Dev/abpvnext/abp-admin-vben/vue-vben-admin/apps/web-antdv-next/src/router/guard.ts:107)
- 现有 `BlobAppService` 是通用 CRUD，`BlobUpdateInput` 可修改 `IsPublic`，Vben 页面有编辑和删除入口。聊天附件必须在 API 层保护，界面同时取消对应的直接编辑和删除按钮。通用 Blob 路由保留已核实的公开资源用途，后端根据来源、角色和消息引用识别聊天附件。未归类历史记录进入只读诊断。 [BlobAppService](../../src/IczpNet.Chat.Application/Blobs/BlobAppService.cs) · [更新 DTO](../../src/IczpNet.Chat.Application.Contracts/Blobs/Dtos/BlobUpdateInput.cs) · [Vben Blob API](F:/Dev/abpvnext/abp-admin-vben/vue-vben-admin/apps/web-antdv-next/src/api/chat/blob.ts)
- 首期管理权限只授予元数据访问和受控运维。私有附件的内容仍走现有消息授权。管理员若同时拥有对应聊天身份，可按正常消息入口读取。支持工单可使用仅含诊断字段的结果，正文、文件字节、令牌、签名 URL、物理对象键和完整存储摘要均从管理 DTO 排除。

## 后端执行清单

### A1 明确数据范围和权限

在现有 `ChatPermissions` 与权限定义机制内新增附件管理权限组。以下权限名作为开发契约候选，定稿后由 Vben 按实际 ABP policy 接入。

| 权限 | 允许操作 |
| --- | --- |
| `ChatPermissions.AttachmentManagement` | 查看已授权范围内的列表、详情、汇总及故障状态。 |
| `ChatPermissions.AttachmentManagement.Diagnose` | 查看脱敏引用链，发起只读一致性检查或清理预检。 |
| `ChatPermissions.AttachmentManagement.RetryJobs` | 提交失败的 GIF 传播、清理等任务的重试请求。 |
| `ChatPermissions.AttachmentManagement.Repair` | 提交经预检的引用修复、历史归属迁移或限量回收任务。 |
| `ChatPermissions.AttachmentManagement.ViewAudit` | 查询已授权范围内的运维记录和关联任务。 |

- Application 层的每个方法均检查授权。由当前租户和受信配置确定允许的资源范围，查询参数只能进一步缩小范围。核对 `Blob`、`BlobObject`、消息引用、兑换记录及后台任务的真实租户归属链。现有 `StorageScope` 只描述物理存储域，不能单独作为逻辑附件的权限来源。缺少可验证归属的历史行从租户管理列表排除，交给明确授权的 Host 级核对任务。Host 与租户的授权分别测试。
- 为通用 `BlobAppService` 的更新、删除和创建入口建立资源用途限制。禁止管理调用修改聊天附件的 `IsPublic`、状态、引用计数、物理对象 ID 或对象键。拒绝直接删除聊天附件的逻辑记录与物理字节。现有客户端使用的公开资源编辑行为由对应资源用途保留。
- 权限授权同时验证角色、所属范围和目标对象。前端菜单显示只负责导航。接口访问拒绝记录采用统一业务错误，返回内容中不暴露越权目标详情。

### A2 查询和诊断契约

在 Chat Application.Contracts 定义只读 DTO 和输入，Application 编排权限与诊断，Domain 复用附件生命周期规则，EntityFrameworkCore 提供投影、关联和游标查询。普通 JSON 接口使用 ABP ConventionalControllers。使用独立管理用例承载物理对象、任务、引用等数据，避免让通用 Blob 更新接口承担新的状态操作。

下列是拟定接口职责。完成后以实际 Swagger 生成的路由和字段为准，后端应在联调前保存路由及响应样例。

| 查询 | 输入及返回 |
| --- | --- |
| 附件概览 | 按当前范围与日期展示逻辑附件数、共享物理对象数、覆盖范围内的重复字节估算、旧版未关联附件、待处理回收、GIF 积压。返回统计时间与口径。无法确定的旧附件占用单独列示。 |
| 逻辑附件列表与详情 | 支持 BlobId、文件名关键词、上传身份、会话、日期、媒体类型、状态、用途和异常标记。详情返回生命周期、上传及过期时间、裁剪后的身份标识、角色、衍生件数、逻辑引用数和是否共享物理对象。 |
| 物理对象列表与详情 | 支持存储域、容器、状态、日期与异常标记。返回对象逻辑 ID、大小、记录计数、实际有效逻辑引用数和检测时间。对无权限引用只显示允许披露的聚合或省略。 |
| 附件引用与授权诊断 | 以指定 BlobId 查消息、发送／转发／历史来源、关联会话和引用状态。诊断输入另支持明确的 `sessionUnitId`、`messageId`、`rootMessageId`。后台复用现有授权判断，返回经过裁剪的拒绝原因和缺失关系。全程无需模拟登录用户或签发附件下载地址。 |
| 运维任务与审计 | 按任务类别、状态、时间、关联 ID 查找。返回最近执行结果、下次重试时间、尝试数、操作者和审计关联号。重试和修复动作返回同一体系的任务 ID。 |

- 明确区分 `Blob.RefCount` 统计消息引用，`BlobObject.RefCount` 统计逻辑附件引用。界面同时展示记录值和实际值，以及最近核对时间。空间估算只在统一过滤范围、去重覆盖且账目可核对的集合中计算。
- 查询统一返回投影 DTO。热表以创建时间加稳定 ID 作游标，对引用明细使用 BlobId 与消息 ID 索引。限制排序白名单、时间范围和页大小。聚合指标优先重用可持久化统计口径，记录统计时点，禁止逐行查询 MinIO、消息正文或全表扫描。
- 关联 ID 可复制。大消息 ID 在浏览器使用字符串，时间由服务端返回统一格式并按现有时区工具展示。异常原因使用稳定业务码，例如缺引用、源用途待核对、对象未就绪、物理计数不一致、任务待重试。已存数据库诊断可与对象存储探测结果区分显示。

### A3 受控运维操作

| 动作 | 后端行为 |
| --- | --- |
| 诊断检查 | 从显式的附件、物理对象或受限时间范围发起只读检查。返回涉及对象数、引用差异、跳过原因、样例与任务 ID。对象存储探测应限频，通过 Worker 执行。 |
| 重试 GIF 或回收任务 | 仅允许可重试状态。复用 GIF 事务外箱和附件清理 Worker，按任务 ID 与操作幂等键合并重复提交。接口返回受理状态，不同步触发转码或删除。 |
| 引用补齐与计数校正 | 先预检并记录目标集、范围、预计影响和状态版本。提交时校验预检仍有效，由 Worker 按结构化消息关系补引用。按真实有效引用在数据库事务内校正计数，记录实际影响和跳过原因。 |
| 历史公开附件迁移或孤儿回收 | 先预检并记录受控候选集，明确公开资源、用途不明和仍有引用的跳过条件。执行前再次核对状态。物理删除只由现有 Worker 认领后执行，校验实际引用与对象版本。执行记录包含成功、失败及待重试明细。 |

- 修改类操作要求原因及客户端生成的操作幂等键。工作流采用「预检 → 确认 → 受理 → 查询结果」。对状态变化、重复提交或过期预检分别返回可识别结果。限制每批大小和作用范围，失败可续跑。
- 使用当前 ABP 审计能力。记录操作者、租户／范围、动作、目标 ID、预检 ID、理由、请求关联号、改动前后状态和结果。结合现有持久化 Job/Outbox 记录运行进度。若现有持久化实体无法表示操作生命周期，先评审新增表、索引、保留期和迁移。 [GIF 外箱服务](../../src/IczpNet.Chat.Domain/Blobs/VideoGifPropagationOutboxService.cs) · [清理服务](../../src/IczpNet.Chat.Domain/Blobs/TempBlobCleanupService.cs) · [Vben 审计页](F:/Dev/abpvnext/abp-admin-vben/vue-vben-admin/apps/web-antdv-next/src/views/system/audit-log/audit-log-list.vue)

## Vben 执行清单

1. **接管现有路由。** 在 `router/routes/modules/chat.ts` 更新 `ChatBlob` 权限和菜单标题，保持深链接。保留现有 `useVbenVxeGrid`、本地化和错误处理方式。动作按钮分别按现有 `useAccess` 机制裁剪。将缺权限、查询为空、记录未归类和服务异常显示为不同状态。
2. **实现附件列表与详情。** 在 `views/chat/blob` 内扩展筛选与详情抽屉。首页用「概览」「逻辑附件」「物理对象」「任务与审计」组织入口。列表展示状态、角色、归属、时间、计数和异常。详情显示脱敏引用链，可复制 BlobId、消息 ID 和任务 ID。支持按异常打开并预填诊断，切换筛选时清理旧游标，避免慢响应覆盖新结果。
3. **接入请求层。** 在 `api/chat` 增加管理 API 的类型与请求函数，复用 `requestClient` 和已核对的 ABP 契约。查询分页使用后端约定，写操作显式传原因、预检 ID 和幂等键。长时间任务显示受理及进度，采用用户刷新或有节制轮询，离开页面及时结束。
4. **替换直接编辑和删除。** 聊天附件页去掉直接修改公开状态和直接删除入口。详情根据权限及状态展示「授权诊断」「预检」「重试」「提交修复」。确认页展示预计影响、排除量、状态版本和理由输入。提交成功后进入任务详情，可跳转既有审计日志并带任务筛选。
5. **兼容和回退。** 保持原对象存储深链接。在读路由可用后再逐项打开运维按钮。关闭 Vben 写操作时，由后端权限或开关同时拒绝请求。保留只读和任务进度查询，已经受理的 Worker 任务沿既有规则完成或按任务状态取消。

## 验收与交付

| 场景 | 验收结果 |
| --- | --- |
| 只读、诊断、重试、修复角色 | 菜单和按钮按权限显示，直接请求接口仍校验权限。操作者无法查询跨租户任务或推断私有附件信息。 |
| 旧 CRUD 加固 | 对聊天附件的公开状态编辑、直接删除和敏感字段赋值均由 API 拒绝。已确认的通用公开资源调用通过兼容测试。 |
| 常规与历史附件 | 独立上传、同账号多身份、普通转发、嵌套 History、撤回和个人删除均能解释真实引用与权限状态。未归类记录不会误判为可公开或可回收。 |
| 预检与执行并发 | 两个管理员提交相同操作只产生一份有效任务。预检后实际引用增加时阻止回收。Worker 中断、重启和重试可恢复，审计状态完整。 |
| 生产规模和界面 | 在接近生产的数据量下查看过滤／翻页执行计划与响应时间。大列表操作有边界，不加载正文、附件字节或任意对象地址。 |
| 构建与上线 | Chat 完成受影响项目的构建、权限和生命周期集成测试。Vben 运行 `pnpm --filter @vben/web-antdv-next typecheck`、`pnpm --filter @vben/web-antdv-next build` 及附件管理定向测试。预生产使用实际 Swagger、SQL Server 和 MinIO 完成联调，记录存量问题与本轮新增问题。 |

交付物包括管理 API 契约、角色权限矩阵、Vben 页面、运维与审计记录、回归结果以及迁移或配置说明。正式环境的回填、清理和权限启用由既有发布流程执行。

本方案基于当前仓库入口编写，仅交付本地文档。
