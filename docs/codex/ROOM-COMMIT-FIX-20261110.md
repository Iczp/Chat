# 群创建事务与缓存修复

原群创建在 SQL 提交前写入会话缓存和连接池，再调用使用独立事务的消息发送器。内部事务等待外层事务未提交的会话行，导致请求超时；外层回滚后，已写入 Redis 的群成员和会话索引仍存在。

创建流程现在使用事务性工作单元；调用方没有事务时会开启独立事务。流程先保存群和成员，并准备系统消息；仅在工作单元提交完成后，使用新依赖注入作用域写入会话缓存、连接池并发送系统消息。系统消息客户端 ID 由会话 ID 确定，符合既有发送幂等键长度。该调整只覆盖创建群，未改动邀请成员流程。

## 残留清理

用户确认仅清理失败建群缓存。数据库再次确认对象 6152、会话 `92ae5cfe-f57d-9ef9-a523-753e45fc9b0b` 及其三个会话单元均不存在；Redis Lua 操作先验证三个成员和所有者索引，再原子移除 10 个精确索引成员及 9 个会话专属键，另删除对象 6152 的缓存键。未删除其他缓存或数据库记录。先前隔离压测会话 `d3f290e6-a41b-a217-6546-57d3ea20e685` 的 324 条消息仍在。

## 限制

提交后操作使用进程内 `OnCompleted` 回调，并非持久化 outbox。SQL 提交后若进程退出或 Redis/消息发送失败，群已存在而缓存或系统消息可能不完整；稳定客户端 ID 可防止消息重复，但当前流程没有持久化重试或崩溃恢复保证。邀请成员仍使用原有事务和缓存发布方式，不在本次修改范围内。
